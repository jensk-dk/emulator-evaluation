  - On Linux (x86-64), with the image built from the revision that has the macOS media and graphics changes, the compositor ends every time in one sequence in ARM32 VM mode with emulated graphics at 4K: the Wayland test, then the OpenGL ES test, where it ends at the first OpenGL ES frame (9 of 9 runs; the check `resolution-vm-arm32` fails there, and passes on macOS). ## 5. Stage 4: Media playback
- [x] 5.1 Accept MP2TS, MP4, and MSE-style fragment input and verify each media input path.
  - Implemented as the `media-decode` workload. Verified on Linux (x86-64), on macOS (ARM64) and on Windows (x86-64) in container, host-native VM, ARM64 VM and ARM32 VM modes: each video codec is decoded from MP2TS, from MP4, and from an initialisation segment and media fragments appended one after another to the running decoder; audio-only streams from MP2TS and from MP4.

- [x] 5.2 Decode MPEG-2, AVC, and HEVC video and MP2, AC-3, AAC, and HE-AAC audio; verify each codec.
  - Verified on Linux (x86-64), on macOS (ARM64) and on Windows (x86-64) in all four modes, with FFmpeg's software decoders: every frame of each video stream is decoded, and each audio codec, HE-AAC from MP4 and from MP2TS.
  - The HE-AAC reference tone is a file in the repository (`target/media/heaac-1100hz.aac`): Debian and Ubuntu ship no HE-AAC encoder. It was made once with the Fraunhofer FDK AAC encoder; `target/media/build-media.sh` says how.

Container and host-native VM modes dropped none through Wayland, OpenGL ES and Vulkan.
  - The dropped-frame values are the players' own counts (mpv's, and the Flutter application's). After the browser's count proved wrong for MSE playback (6.2), they were compared with the display's own record on macOS on 2026-11-15, at 1080p with emulated graphics: in container, host-native VM and ARM64 VM modes through every technology, and through Wayland in ARM32 VM mode, the display showed at most three fewer new frames than the player counted as shown. Through OpenGL ES in ARM32 VM mode mpv counted 19 to 45 of a stream's 125 frames as shown and the display showed 13 to 34, six to eleven fewer each time, so the value understates the loss there by that much. The workload and its value are unchanged; counting playback by the display's record, as MSE playback is, is not done. Not compared on Windows or Linux.
  - Open: Vulkan and Flutter video in ARM32 VM mode, for the reasons under 4.1 (Mesa's CPU Vulkan driver crashes on 32-bit ARM; no Flutter SDK for it).
  - Open: in ARM32 VM mode the Wayland compositor ended during playback (the instability noted under 4.1): on Linux in both runs made, during one to three of the six playbacks through Wayland and OpenGL ES; on macOS in the one run made, during two of them; on Windows in the one run made, during five of them. ## 7. Stage 6: Windowed display UX
- [ ] 7.1 Implement windowed and full-screen modes with a hotkey to switch between them and verify both transitions.
  - Implemented 2026-11-15 as the launcher's own window (`emu run --window`, `--fullscreen`; `emulator/gui/viewer.py`), in container and in VM mode. It follows the target's display with the remote framebuffer protocol: QEMU's VNC server in VM mode, and in container mode a program in the target that captures the compositor's output and serves it on a port published on the host's loopback address (`target/src/emuscreen.c`). Weston's own VNC backend was not usable for that: it insists on an encrypted login. Ctrl+Alt+F or F11 switches between the window and full screen; full screen has no toolbar.
  - Native crash corrected on Ubuntu 22.04 x86-64, Python 3.10.12, 2026-11-19: VM channel playback aborted with `free(): invalid pointer`. A minimal QObject signal callback reproduced it without QEMU, RedRat, images or threads: PySide6 6.12.0 decreased Python's `True` reference count once per delivery; 6.11.3 kept it stable across 1,000 deliveries.
